# Fuel G01 - Granular write permissions (2026-11-12)
**Implemented:** twelve narrower write permissions, one per Fuel area, that sit alongside FUEL_MANAGE: FUEL_OPERATIONS_MANAGE (tanks, receipts, dispatches, deliveries, suppliers), FUEL_STOCK_MANAGE, FUEL_ORDERS_MANAGE (orders, loading, invoicing), FUEL_PURCHASING_MANAGE, FUEL_CUSTOMERS_MANAGE, FUEL_COMPLIANCE_MANAGE, FUEL_TRANSPORT_MANAGE, FUEL_FORECOURT_MANAGE (pump setup, shift reversal), FUEL_SUPPLIER_INVOICE_MANAGE, FUEL_PRICING_MANAGE, FUEL_PORTAL_MANAGE, FUEL_DISTRIBUTION_MANAGE. A tenant can now give someone price changes without everything else.
**Preserved (existing tenants keep access):** every endpoint that required FUEL_MANAGE still accepts FUEL_MANAGE (it is the umbrella), so no existing role loses anything and no role is changed. Only ADMIN is given the new permissions by the migration. Permissions that already existed for specific acts (adjust, approve, supervise, evidence verify, variance review, credit override, margin read, configuration) are untouched. Settings keeps FUEL_MANAGE alone; division/configuration keeps FUEL_CONFIGURATION_MANAGE.
**Not done:** division- or site-scoped permissions (a permission limited to one division or site). The division switches already gate which divisions a tenant sees, and site scoping would need a scope model in IAM; this is left as a decision rather than invented here. Also not changed: read permissions (FUEL_READ stays one read tier).
**Files:** V666 migration; the 12 Fuel controllers (annotation text only); web tabs use the narrower permission as well as FUEL_MANAGE to show write buttons.
**DB (V666):** inserts 12 rows into permissions (module fuel, verb MANAGE, grantable by ADMIN) and grants them to ADMIN.
**Security:** FuelEndpointSecurityTest gained two checks: no endpoint may be guarded by FUEL_MANAGE alone (except Settings), and every area permission must be seeded for module fuel and given to ADMIN. PermissionConsistencyTest already checks every @PreAuthorize permission exists in the database.
**Tests:** Java tests parse-checked and the two scans emulated in Python over the real files; not run by Maven here.
**Risks:** the sensitivity labels (FINANCIAL/SENSITIVE/NORMAL) are my classification; adjust in the migration if your IAM policy differs. A tenant that wants a role to lose FUEL_MANAGE and use only the narrow ones must re-grant deliberately.
